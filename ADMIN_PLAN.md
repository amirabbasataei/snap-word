## Technology decision
| Concern | Choice | Why |
|---|---|---|
| Backend | Existing Go/Gin server, new `handler/admin_*.go` → `service/admin_*.go` → `repository/admin_*.go` (3 layers, per CLAUDE.md) | Reuses repos/services, DB, Redis, Hub; no new service on the 2 GB box |
| Frontend | React 18 + TypeScript + Vite, in a new top-level `admin/` dir | Mature ecosystem for data-heavy dashboards; Node 22 + pnpm already installed |
| Styling | Tailwind CSS v4 with CSS-variable tokens + Radix primitives (shadcn/ui-style components, copied in, not a dependency) | Native `dir="rtl"` support, logical properties (`ps-`/`pe-`/`start-`/`end-`) |
| Data | TanStack Query + React Router | Caching, pagination, mutations with invalidation |
| Charts | Apache ECharts (`echarts-for-react`) | Smooth gradient areas, rounded gradient bars, donut — exactly the reference's chart style; custom font + Persian-digit formatters |
| Icons / dates | `lucide-react`; `date-fns-jalali` | Jalali dates; Persian digits via a small `toFa()` util (mirror of `client/lib/core/utils/persian_digits.dart`) |
| Serving | `vite build` → `backend/internal/adminui/dist`, embedded with `//go:embed all:dist`, served by Gin at `/admin/*` with SPA fallback | One deploy, same origin → httpOnly cookies, no CORS |
| Auth | `admin_users` table, bcrypt, **server-side sessions in Redis**, httpOnly `SameSite=Strict` cookie, TOTP 2FA (A7) | Revocable; no admin JWT confusion with player JWTs |

**Security note (public over plain HTTP, user's choice):** passwords and session cookies are sniffable until TLS exists. Mitigations built in: short idle session TTL (2h, absolute 12h), login rate-limit + lockout, mandatory TOTP from A7, role-based permissions, full audit log, optional `ADMIN_IP_ALLOWLIST` env. Adding a domain + TLS later is strongly recommended and needs no panel changes.

Backend + `/` page built as specified, with these decisions/deviations:
- **Endpoints (read-only, any role, viewer included):** `GET /api/v1/admin/dashboard/summary` and `GET /admin/dashboard/timeseries?days=N` (default 30, 1–90; otherwise `400 validation_error`). Files: `repository/admin_dashboard.go`, `service/admin_dashboard.go`, `handler/admin_dashboard.go`; `Hub.Snapshot()` (`ws/hub.go`) + `Room.snapshot()`; `NotificationService.Configured()`; matchmaking's mode list is now the shared `queueModes` var. - **Counts exclude the seeded AI user** (`config.SystemAIUserID`) from users/coins; "registered" = `phone_verified_at IS NOT NULL`. Premium = `premium_until > now()`.
- **Match classification is derived, not stored.** The server cannot tell a solo game from an on-device vs-AI game (`SyncService` uploads one `match_players` row, no opponent type), so the donut/bars use four real buckets: «تک‌نفره و هوش مصنوعی (روی دستگاه)» (classic, 1 player), «رودررو» (2 humans), «هوش مصنوعی آنلاین» (matchmaking fallback, `is_ai`), «چالش روزانه» (`mode='daily'`). This replaces the plan's solo / AI / 1v1 / daily split. Matches are bucketed by `COALESCE(started_at, created_at)` (uploaded games count on the day played, not the day synced); status `pending` is excluded. Legacy `time_attack` rows count as solo/versus.
- **No invented metrics:** no DAU/MAU history (`player_stats` keeps only the last played date), and premium / coins-in-circulation / unclaimed rewards have no history, so those tiles show a number only (no sparkline, no delta). Deltas = last 7 days vs the 7 before (today included, so it is partial); omitted when the previous week is 0. `coins_claimed` (claimed inbox rewards per day) is in the time series and surfaces as a «۷ روز» caption on the unclaimed-rewards tile.
- **Live numbers** (`live.*`) come from the in-memory hub (this process only — fine while there is one app instance) and `LLEN queue:<mode>`; players = human sockets attached to rooms (AI excluded).
- **Charts:** `echarts@6.1.0` + `echarts-for-react@3.0.6`, tree-shaken (`components/charts/EChart.tsx`), colours resolved from the CSS tokens at runtime (`useChartColors`, re-read when `data-theme` flips). RTL: the time axis is reversed (newest on the reading-start side) with the value axis at the start side; legends are HTML (not canvas) and each chart has an `aria-label` summary. The dashboard route is lazy-loaded (main bundle 391 kB, Dashboard chunk 589 kB / 200 kB gzip). The CJS default import of `echarts-for-react/lib/core` arrives as a namespace object in the production bundle — `EChart.tsx` unwraps it (it crashed with React #130 otherwise; dev/vitest did not show it).
- **Palette check** (`validate_palette.js`, dataviz skill): mode colours use the fixed order blue → orange → yellow → green. Dark CVD separation is the 6.5 floor (yellow↔green, protan) and the brand accents sit outside the validator's lightness band, so identity is never colour-alone: HTML legends carry the counts, tooltips list every value, and segments have a 2px surface gap.
