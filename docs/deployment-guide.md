# Deployment guide — Zanjir backend + admin panel

End-to-end guide for building, shipping, configuring and operating the Go backend and the
embedded admin panel. It is written from the actual files in `scripts/`, `deploy/`,
`backend/` and `admin/` (reviewed 2026-10-27). Where this guide and a script disagree, the
script wins — and the disagreement is listed in [§12 Known gaps](#12-known-gaps-found-in-this-review).

Related docs: [`server-runbook.md`](server-runbook.md) (host operations: adding sites, HTTPS,
backups) · [`server-plan.md`](server-plan.md) (why the host is laid out this way) ·
[`../ADMIN_PLAN.md`](../ADMIN_PLAN.md) (panel stages) · [`../CLAUDE.md`](../CLAUDE.md) (product spec).

## 1. Architecture at a glance

```
 Visitor / app ──► ArvanCloud edge (TLS, CDN) ──► origin 185.110.191.158
                                                       │  :80 / :443
                                                    nginx (host, systemd)
                                                       │  127.0.0.1:18080
                          ┌────────────────────────────┴──────────────┐
                          │ docker compose project "wordchain"        │
                          │  app   (Go binary; REST + WS + /admin/)   │
                          │  redis (128 MB, allkeys-lru)              │
                          └────────────────┬──────────────────────────┘
                                           │ external docker network "infra"
                                  infra-postgres  (shared PostGIS 16, 127.0.0.1:5432)
```

Key facts:

- **One binary serves everything.** The Go server exposes the REST API (`/api/v1`), the
  WebSocket (`/api/v1/ws`), `/health`, and the **admin panel at `/admin/`**. The panel is a
  React SPA compiled by Vite into `backend/internal/adminui/dist` and baked into the binary
  with `//go:embed all:dist`. There is no separate panel deployment: **a panel change is a
  backend deploy.**
- **Images are built on your machine, not the server.** The host is 1 vCPU / 2 GB RAM shared
  with other sites. `deploy_backend.sh` builds `linux/amd64` locally and ships the image over
  SSH (`docker save | ssh docker load`).
- **Migrations run at server start** (embedded via `io/fs`, `golang-migrate`). Deploying a new
  image migrates the shared database.
- **Postgres is shared** (`infra-postgres`, database/role `wordchain`); Redis is per-site.
- **Only nginx is public** (22/80/443). The app binds `127.0.0.1:18080`; Docker bypasses ufw,
  so a container port must never be published without `127.0.0.1:`.
- **Public URLs:** API `https://amirabbasataei.ir/api/v1/…`, panel `https://amirabbasataei.ir/admin/`.

### Where each thing lives

| Concern | Repo source | On the server |
|---|---|---|
| App image | `backend/Dockerfile` | `wordchain-app:<tag>` (3 newest kept) |
| App compose | `deploy/sites/wordchain/compose.yml` | `/opt/wordchain/compose.yml` |
| App secrets / config | — (never in git) | `/opt/wordchain/.env` (root, 600) |
| FCM key | — | `/opt/wordchain/secrets/fcm-service-account.json` |
| Shared Postgres | `deploy/host/compose.yml` | `/opt/infra/compose.yml`, container `infra-postgres` |
| Postgres superuser pw | — | `/opt/infra/.env` (`POSTGRES_PASSWORD`) |
| nginx shared config | `deploy/host/nginx/{conf.d,snippets}` | `/etc/nginx/{conf.d,snippets}` |
| nginx Zanjir site | `deploy/host/nginx/sites/zanjir.conf` + `snippets/site-zanjir.conf` | `/etc/nginx/sites-available/zanjir` |
| nginx Zanjir HTTPS block | generated by `site-https` (not in git) | `/etc/nginx/sites-available/zanjir-https` |
| Host CLI | `deploy/host/bin/*` | `/opt/infra/bin` → symlinked in `/usr/local/sbin` |
| Timers | `deploy/host/systemd/*` | `/etc/systemd/system` |
| Backups | `deploy/host/bin/pg-backup` | `/var/backups/infra/{daily,weekly}` |

## 3. Configuration reference

All runtime config is environment variables, read by `backend/internal/config/config.go`.
In production they come from `/opt/wordchain/.env` through `deploy/sites/wordchain/compose.yml`.

| Variable | Prod source | Required | Notes |
|---|---|---|---|
| `APP_IMAGE` | `.env`, **written by `deploy_backend.sh`** | yes | `wordchain-app:<hash>[-dirty]-<MMDDhhmm>`; compose refuses to start without it |
| `DB_PASSWORD` | `.env` | yes | from `site-db create wordchain`; compose builds `DATABASE_URL` from it |
| `JWT_SECRET` | `.env` | yes | random ≥32 bytes. Compose enforces non-empty (`:?`); **the server itself does not** (see §12) |
| `JWT_ACCESS_TTL` / `JWT_REFRESH_TTL` | `.env` | no | default `15m` / `720h` |
| `CORS_ORIGINS` | `.env` | no | comma-separated; empty by default |
| `FCM_PROJECT_ID` | `.env` | for push | Firebase project `zanjir-269aa`. Key file mounted at `/secrets/…` |
| `GAME_EPOCH_DATE` | `.env` | no | Daily Challenge day #1, default `2025-01-01` — **do not change after launch** |
| `KAVENEGAR_API_KEY` / `KAVENEGAR_OTP_TEMPLATE` | `.env` | for SMS | empty key = OTP is logged, not sent (dev bypass code `1111`) |
| `ADMIN_API_KEY` | `.env` | recommended | enables `X-Admin-Key` (scripts act as `owner`, actor `script`). With no key **and** no admin user the whole admin API/panel 404s |
| `ADMIN_SESSION_TTL` | `.env` | no | idle timeout of panel sessions, default `2h` (absolute cap fixed at 12 h) |
| `ADMIN_IP_ALLOWLIST` | `.env` | no | comma-separated IPs/CIDRs; others get 404 on `/api/v1/admin/*`. Empty = open |
| `PORT`, `REDIS_URL`, `ENV`, `LOG_LEVEL`, `FCM_SERVICE_ACCOUNT_JSON` | **hard-coded in compose** | — | `ENV=prod` (JSON logs, gin release mode), `LOG_LEVEL=info`, Redis = the sibling container |
| `OTP_CODE_TTL`, `OTP_RESEND_COOLDOWN` | **not wired** in prod compose | no | code defaults (2 m / 120 s) apply; add them to compose + `.env` to change |

Rules for `/opt/wordchain/.env`: root-only (`chmod 600`), never commit, never put in a
`docker-compose` `environment:` literal. Changing it needs `cd /opt/wordchain && docker compose up -d app`
(compose recreates the container when interpolated values change).

Minimal `.env`:

```dotenv
APP_IMAGE=            # filled by deploy_backend.sh
DB_PASSWORD=<from site-db create wordchain>
JWT_SECRET=<openssl rand -hex 32>
ADMIN_API_KEY=<openssl rand -hex 32>
FCM_PROJECT_ID=zanjir-269aa
KAVENEGAR_API_KEY=<when the account exists>
KAVENEGAR_OTP_TEMPLATE=wordchain-otp
# optional: ADMIN_SESSION_TTL=2h  ADMIN_IP_ALLOWLIST=203.0.113.7,10.0.0.0/8  CORS_ORIGINS=…
```

## 4. First-time setup of a fresh host

The repo codifies everything *after* a bare Ubuntu box with Docker and nginx exists. Steps 1–2
below are **reconstructed from the runbook's "Security baseline"; they are not scripted**.

### 4.1 Base OS (manual)

```bash
# swap (2 GB) + low swappiness
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab && echo 'vm.swappiness=10' > /etc/sysctl.d/99-swap.conf

# firewall: only SSH + web
ufw default deny incoming && ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw enable

# SSH keys only
printf 'PasswordAuthentication no\nPermitRootLogin prohibit-password\n' > /etc/ssh/sshd_config.d/00-hardening.conf
systemctl reload ssh      # keep a second session open until you confirm you can still log in

apt-get install -y nginx rsync docker.io docker-compose-v2     # or Docker's official repo
```

### 4.2 Shared infrastructure (Postgres, nginx config, timers)

```bash
# on the server: the compose file needs the superuser password before first start
ssh root@HOST 'install -d -m 700 /opt/infra && umask 077 && echo "POSTGRES_PASSWORD=$(openssl rand -base64 33 | tr -dc A-Za-z0-9)" > /opt/infra/.env'

# from your machine
bash scripts/host_sync.sh --dry-run     # preview
bash scripts/host_sync.sh               # rsync deploy/host → /opt/infra, then run install.sh
```

`install.sh` (idempotent) will: symlink the CLI into `/usr/local/sbin`; start `infra-postgres`
(`up -d --wait`, creates the `infra` docker network); install and enable the three timers
(`infra-backup`, `infra-restore-test`, `arvan-ips`); install the nginx shared config and the
managed site files, refresh the ArvanCloud IP ranges, `nginx -t`, then **reload** (on a bad
config it restores the previous `/etc/nginx`). It never overwrites `/opt/infra/.env`,
`/opt/infra/ports` or enabled `post-backup.d/*.sh` hooks.

### 4.3 The Zanjir site

`new-site` is for *new* sites; Zanjir's nginx files are already in git, so create only the DB
and directory (new-site would refuse because the nginx site exists):

```bash
ssh root@HOST
PW=$(site-db create wordchain)                 # role+db "wordchain"; prints a password once
install -d -m 755 /opt/wordchain/secrets
umask 077
cat > /opt/wordchain/.env <<EOF
DB_PASSWORD=$PW
JWT_SECRET=$(openssl rand -hex 32)
ADMIN_API_KEY=$(openssl rand -hex 32)
FCM_PROJECT_ID=zanjir-269aa
EOF
chmod 600 /opt/wordchain/.env
# FCM push (optional until needed): copy the Firebase service-account JSON to
#   /opt/wordchain/secrets/fcm-service-account.json   (chmod 600)
```

`/opt/infra/ports` already reserves `18080 wordchain`.

### 4.4 First deploy, admin user, catalogue seed

```bash
bash scripts/deploy_backend.sh                 # §5 — creates the redis container too
bash scripts/admin_user.sh <username> owner    # §7 — prompts for a password on the server
bash scripts/perks_admin.sh seed               # uploads the 16 seed avatars (needs ADMIN_API_KEY in .env)
```

Taunts are seeded by migration `011`; avatars are not (binary data), hence `seed`.

### 4.5 DNS and HTTPS

1. ArvanCloud: add the domain, set the registrar nameservers to Arvan's, `A @` and `www` →
   server IP, proxy **on**. Wait for `dig +short NS <domain>` to show `*.ns.arvancdn.ir`.
2. Check the origin before HTTPS: `curl -H 'Host: amirabbasataei.ir' http://SERVER_IP/health`.
3. `ssh root@HOST 'CERTBOT_EMAIL=you@example.com site-https zanjir'` — Let's Encrypt via HTTP-01
   (`/var/www/acme`), writes `sites-available/zanjir-https`, reloads nginx. Use `--staging`/`--dry-run`
   first. **Do not enable ArvanCloud's "force HTTPS" until this succeeds.**
4. Arvan panel → HTTPS settings: enable HTTPS + free edge cert; origin protocol **HTTPS (443)**
   once the origin cert exists; only then the edge HTTP→HTTPS redirect, later HSTS.
5. The :80 server itself 301-redirects visitors who came over plain HTTP (`$edge_proto`);
   ACME challenges are exempt.

## 5. Deploying the backend + panel (routine release)

```bash
bash scripts/deploy_backend.sh             # build → ship → restart → health check
bash scripts/deploy_backend.sh --dry-run   # build only; shows compose.yml diff vs the server
bash scripts/deploy_backend.sh --logs      # after success, tail app logs
```

### What the script does, in order

| # | Step | Command / effect | Fails if |
|---|---|---|---|
| 1 | Tag | `<git short hash>[-dirty]-<MMDDhhmm>`; `-dirty` = uncommitted changes under `backend/` or `admin/` | — |
| 2 | **Build panel** | `pnpm -C admin install --frozen-lockfile && pnpm -C admin build` → `tsc --noEmit` + `vite build` into `backend/internal/adminui/dist` (cleared first) | lockfile drift, TS errors |
| 3 | Vet backend | `cd backend && go build ./...` | compile errors |
| 4 | Build image | `docker build --platform linux/amd64 -t wordchain-app:$TAG backend` (two binaries: `/server`, `/adminctl`; alpine 3.19 runtime) | — |
| 5 | *(dry-run stops here)* | prints `diff` of server `compose.yml` vs repo | — |
| 6 | Ship | `docker save \| gzip -1 \| ssh HOST 'gunzip \| docker load -q'` | SSH down |
| 7 | Sync compose | `scp deploy/sites/wordchain/compose.yml → /opt/wordchain/compose.yml` | — |
| 8 | Switch | sets `APP_IMAGE` in `/opt/wordchain/.env` (appends if absent), `docker compose up -d --remove-orphans app`, prunes all but the 3 newest `wordchain-app` images | — |
| 9 | Health | polls `http://127.0.0.1:18080/health` on the server every 2 s, 30× (60 s) | prints last 40 log lines, exits 1 |

`/health` returns 200 `{"status":"ok"}` only when **both** Postgres and Redis answer within 2 s
(`503 db_unavailable` / `redis_unavailable` otherwise).

### Release checklist

1. `git status` clean and on the commit you intend to ship (a `-dirty` tag is a warning sign).
2. Backend: `cd backend && go test ./internal/...` (repo tests need `TEST_DATABASE_URL`, see CLAUDE.md § Testing).
   Panel: `pnpm -C admin typecheck && pnpm -C admin lint && pnpm -C admin test`.
3. New migration? Read §9 first — **deploy applies it immediately and rollback does not undo it.**
4. New env var? Add it to `deploy/sites/wordchain/compose.yml` (it is **not** read from `.env`
   unless listed there), add the value to `/opt/wordchain/.env` on the server, then deploy
   (the script syncs compose before `up`). Put a blank/commented entry in `.env.example`.
5. `bash scripts/deploy_backend.sh --dry-run`, review the compose diff, then run for real.
6. Verify (§8). Update `CLAUDE.md` if behaviour or ops changed.

### Expected impact

`up -d app` recreates the container: a few seconds of downtime, and open WebSockets drop. The
client reconnects with exponential backoff and the server holds a room 30 s, so an in-flight 1v1
match normally survives; avoid deploying during peak hours anyway. There is no blue/green.

## 6. Admin panel specifics

- **Build output:** `admin/` → `backend/internal/adminui/dist` (only `dist/.gitkeep` is tracked).
  `vite.config.ts` fixes `base: '/admin/'`; the panel is always on the backend's own origin at `/admin/`.
- **Serving:** `handler.AdminUIHandler` at `/admin` and `/admin/*` — SPA fallback, immutable caching
  for `assets/`, strict CSP, `X-Frame-Options: DENY`. It 404s exactly like the API when no admin
  user and no key exist, obeys `ADMIN_IP_ALLOWLIST`, and answers **503 "panel not built"** if the
  binary was compiled without a panel build.
- **Do not build the image by hand without the panel.** `backend/Dockerfile` does *not* build the
  panel — it only compiles Go with whatever is in `dist/`. Always go through `deploy_backend.sh`
  (or run `pnpm -C admin build` first). The same applies to local `docker compose up --build`.
- **After every panel change:** rebuild + redeploy the backend (locally:
  `pnpm -C admin build && cd backend && docker compose up -d --build app`).
- **Local panel dev:** `pnpm -C admin dev` → http://localhost:5173/admin/ (proxies `/api` to `localhost:8080`).
  `/admin/kit` (component gallery) exists only on the dev server.
- **Cookie:** `zanjir_admin`, httpOnly, `SameSite=Strict`, `Secure` only when the request is TLS /
  `X-Forwarded-Proto: https` (nginx forwards `$edge_proto`). Cookie-authenticated mutations require
  the header `X-Requested-With: zanjir-admin`.
- **Login throttling, two layers:** nginx `admin_login` zone (5 req/min/IP, burst 5, in
  `snippets/site-zanjir.conf`) and the app's own lockout (5 per IP / 10 per username per 15 min).
- **Client IP trust:** nginx overwrites `X-Forwarded-For` with the real visitor IP (ArvanCloud ranges
  are the only trusted proxies, `00-realip-arvan.conf`, refreshed weekly). That is what makes
  `ADMIN_IP_ALLOWLIST` and the lockout meaningful; the app (gin) trusts all proxies, so it must
  never be reachable except through nginx.

## 7. Admin accounts & maintenance scripts

All scripts take `WORDCHAIN_HOST` to override the default `root@185.110.191.158`.

### Accounts — `scripts/admin_user.sh`

```bash
bash scripts/admin_user.sh amirabbas owner          # create (roles: owner|operator|viewer; default owner)
bash scripts/admin_user.sh --set-password amirabbas
bash scripts/admin_user.sh --disable operator1      # also ends their sessions
bash scripts/admin_user.sh --enable  operator1
```

Runs `docker compose exec app /adminctl …` over `ssh -t`, so the password is typed into
`adminctl`'s no-echo prompt on the server (never argv/history). Username
`^[a-z][a-z0-9_.-]{2,31}$`, password 10–72 chars. Non-interactive (stdin) variant on the server:
`printf '%s\n' "$PW" | docker compose -f /opt/wordchain/compose.yml exec -T app /adminctl create-user NAME owner`.
`adminctl` talks straight to the DB, so it works before any admin exists — this is how the first owner is made.
Roles: `viewer` read-only; `operator` can mutate (all mutations need a reason and are audited); `owner` everything
(phone numbers are masked server-side for non-owners).

### Catalogues — `scripts/perks_admin.sh` (taunts/avatars)

```bash
bash scripts/perks_admin.sh list
bash scripts/perks_admin.sh taunt add hurry_up "عجله کن!" [--order N]   |  taunt rm <id>
bash scripts/perks_admin.sh avatar add <id> file.png [--order N]       |  avatar rm <id>
bash scripts/perks_admin.sh seed
```

Runs `curl` *on the server* against `127.0.0.1:18080` with `ADMIN_API_KEY` read from
`/opt/wordchain/.env` there, so the key never crosses the network. Live immediately, no release.
The panel manages the same catalogues (`/admin` → Taunts / Avatars). nginx also exposes
`/api/v1/admin/*` publicly (key/session protected) — keep using this SSH path for key access.

### Premium / coins — admin panel only

Granting or revoking premium and adjusting coins is done in the panel (Users → user detail; role ≥ operator, reason
required, audited). The old SSH scripts `grant_premium.sh` / `grant_coins.sh` were deleted on 2026-10-27.

## 8. Verification after a deploy

Run from your machine unless noted.

```bash
H=root@185.110.191.158
ssh $H 'curl -fsS http://127.0.0.1:18080/health'                       # {"status":"ok"}
curl -fsS https://amirabbasataei.ir/health                             # through Arvan + nginx
curl -sI  https://amirabbasataei.ir/admin/ | head -5                   # 200, CSP, X-Frame-Options: DENY
curl -s -o /dev/null -w '%{http_code}\n' https://amirabbasataei.ir/api/v1/perks/catalog   # 200
ssh $H 'cd /opt/wordchain && docker compose ps && docker compose logs --tail 50 app'
ssh $H 'grep ^APP_IMAGE /opt/wordchain/.env; docker images wordchain-app'
```

Then in a browser: log in at `/admin/`, open the dashboard (loads `summary` + `timeseries`), confirm the
build is the new one (hard refresh; assets are content-hashed). Log lines to look for at startup:
`starting wordchain backend`, no `migrations failed`, no `redis connection failed`.

| Symptom | Likely cause |
|---|---|
| `/admin/` shows "panel not built" (503) | image built without `pnpm -C admin build` — redeploy with the script |
| `/admin/` or admin API → 404 | no admin user **and** no `ADMIN_API_KEY`; or your IP is outside `ADMIN_IP_ALLOWLIST` |
| Login → 429 | nginx or app throttle; wait (`Retry-After`) |
| Login works, every mutation 403 `csrf_required` | proxy/client stripping `X-Requested-With` |
| Health 503 `db_unavailable` | `infra-postgres` down/wrong `DB_PASSWORD`; `docker ps`, `docker logs infra-postgres` |
| Container restarts in a loop | `docker compose logs app`: failed migration, missing mandatory var, unreachable DB/Redis |
| Push no-ops | FCM key missing/not readable at `/secrets/fcm-service-account.json` or `FCM_PROJECT_ID` unset |
| 502 from nginx | app not listening on 18080 (still starting/crashed) |
| Ban/permission change "not applied" | panel is read-only role (`viewer`); check `/admin/auth/me` |

## 9. Database & migrations

- Migrations are embedded (`backend/migrations/embed.go`) and applied **automatically at every start**,
  forward-only. Current set: `001`–`014` (latest `014_analytics`). Add new ones as
  `NNN_name.up.sql` + `.down.sql`.
- **Rollback does not roll the schema back.** Reverting `APP_IMAGE` runs an older binary against the newer
  schema. Write migrations expand-then-contract (add nullable columns/tables first; drop in a later release),
  so the previous image keeps working. Never drop/rename a column the previous release still reads.
- Analytics tables are monthly-partitioned: the app ensures partitions at startup and every 5 min; an
  insert with no partition fails, so a long outage across a month boundary self-heals on the next start.
- Take a manual backup before a risky migration: `ssh $H pg-backup` (≈ seconds; see §10).
- Ad-hoc SQL: `ssh $H 'docker exec -it infra-postgres psql -U postgres -d wordchain'`, or a GUI over
  `ssh -L 5432:127.0.0.1:5432 $H`.

## 10. Backups, restore, secrets

- **Nightly** (`infra-backup.timer`, 00:00 UTC ≈ 03:30 Iran, ±10 min): `pg_dump -Fc` of every database,
  `pg_dumpall --globals-only`, Zanjir's Redis `dump.rdb` (hook `backup.d/wordchain-redis.sh`, expects container
  `wordchain-redis-1`), `SHA256SUMS`, per-table row counts. 7 daily + 4 weekly (Fridays) in `/var/backups/infra/`.
- **Weekly restore test** (`infra-restore-test.timer`, Fri 01:00 UTC) restores the newest backup into scratch DBs
  and compares tables/rows: `journalctl -u infra-restore-test`; manual: `pg-restore-test`.
- **Off-server copy is not set up.** The only copies are on the same disk. Enable
  `post-backup.d/offsite.sh.example` (rsync-over-SSH or rclone to ArvanCloud S3) — until then a disk loss loses everything.
- **Restore Zanjir's DB:**
  ```bash
  B=/var/backups/infra/daily/<stamp>
  cd /opt/wordchain && docker compose stop app
  docker exec infra-postgres psql -U postgres -c 'DROP DATABASE wordchain WITH (FORCE)' -c 'CREATE DATABASE wordchain OWNER wordchain'
  docker exec -i infra-postgres pg_restore -U postgres --no-owner --no-acl --role=wordchain -d wordchain < $B/wordchain.dump
  docker compose start app
  ```
  (`must be owner of extension` warnings are harmless.) Redis (weekly leaderboard, admin sessions) restores by
  stopping redis and placing the `.rdb` in its volume; losing it only logs admins out and resets the weekly board.
- **Rotate secrets:** DB password → `site-db password wordchain`, update `DB_PASSWORD`, `docker compose up -d app`.
  `JWT_SECRET` rotation signs every player out. `ADMIN_API_KEY` rotation only affects the SSH scripts.

## 11. Rollback & recovery

**Bad release (fast path):**

```bash
ssh $H 'docker images wordchain-app --format "{{.Tag}}  {{.CreatedAt}}"'      # three newest are kept
ssh $H "sed -i 's|^APP_IMAGE=.*|APP_IMAGE=wordchain-app:<old tag>|' /opt/wordchain/.env \
        && cd /opt/wordchain && docker compose up -d app"
```

Remember the schema stays at the newer version (§9). If the old image cannot run on it, fix forward or restore the
pre-deploy backup. To go back to an older commit not among the kept images: `git checkout <commit>` and run the
deploy script (it ships a new tag).

**Other recovery paths**

- Locked out of SSH: provider web console → `rm /etc/ssh/sshd_config.d/00-hardening.conf && systemctl reload ssh` / `ufw disable`.
- Broken nginx: `nginx -t` names the file; `host_sync.sh` auto-restores the previous config when validation fails.
  Pre-migration config copy: `/root/pre-migration/etc/nginx` (scheduled for deletion).
- Locked-out admin: `bash scripts/admin_user.sh --set-password <name>` or `--enable <name>` (`adminctl` also uses Redis to end the admin's sessions).
- ArvanCloud IP list went stale/wrong: `ssh $H arvan-ips-refresh` (keeps the old file if the new one fails `nginx -t`).

## 12. Known gaps found in this review

Tracked in [`deployment-todo.md`](deployment-todo.md); ordered by impact.

1. **No off-server backups** (§10). Highest operational risk.
2. **Migrations are forward-only on deploy** and image rollback ignores them (§9).
3. **Server accepts an empty `JWT_SECRET`.** Production compose guards it (`${JWT_SECRET:?}`), but the Go code
   falls back to `""`; any other launch path (local compose without the dev default, manual `docker run`) would
   silently sign tokens with an empty key. Add a startup check when `ENV=prod`.
4. **Docs/config drift:** `.env.example` omits `ADMIN_API_KEY`, `ADMIN_SESSION_TTL`, `ADMIN_IP_ALLOWLIST`;
   `OTP_CODE_TTL`/`OTP_RESEND_COOLDOWN` exist in code and `.env.example` but are not passed through the prod compose;
   the local `backend/docker-compose.yml` doesn't pass the two admin vars either.
5. **`backend/Dockerfile` can't build the panel**, so a plain `docker build` / `docker compose up --build` yields a
   binary with a 503 panel. Consider a Node build stage if CI should build images.
6. **Redis eviction policy vs. durable data:** prod Redis runs `maxmemory 128mb` with `allkeys-lru`, but it holds the
   weekly leaderboard and admin sessions. Under memory pressure Redis may evict them. Likely fine at current scale;
   `volatile-lru` (or monitoring `used_memory`) is safer.
7. **`host_sync.sh` can touch every site.** `install.sh` runs `docker compose up -d --wait` on the shared Postgres;
   editing its `command:` args in `deploy/host/compose.yml` recreates the container → brief DB outage for all
   sites. Nginx changes are reloaded (not restarted) and validated, which is safe.
8. **`sites-available/zanjir-https` is generated, not in git.** Rebuilding the host requires re-running
   `site-https zanjir` (and a working DNS/Arvan setup) before HTTPS exists.
9. **Single host, no staging.** `--dry-run` builds and diffs compose but doesn't exercise the image. A cheap
    pre-flight: `docker run --rm wordchain-app:<tag> /server` against a throwaway DB, or deploy to a second
    compose project on another loopback port.
11. Leftovers called out by the runbook: stale `ufw allow 8080/tcp` rule; `/root/pre-migration/` to delete;
    Kavenegar SMS and iOS push (APNs/`GoogleService-Info.plist`) unverified/unconfigured; admin TOTP (stage A7) not built, so the
    panel is protected by password + throttling + optional IP allowlist only.
